```cpp
/**============================================================================
Name        : book_builder.cpp
Created on  : 25.08.2026
Author      : Andrei Tokmakov
Version     : 1.0
Copyright   : Your copyright notice
Description : Builds OrderBook state from market-data updates.
============================================================================**/

#include "book_builder.hpp"

namespace trading::market_data
{
    BookBuilder::BookBuilder(const InstrumentId instrument,
                             OrderBook& orderBook,
                             MarketEventDispatcher& eventDispatcher) noexcept:
        instrument { instrument },
        orderBook { orderBook },
        eventDispatcher { eventDispatcher }
    {
    }

    bool BookBuilder::applySnapshot(const Snapshot& snapshot) const
    {
        if (snapshot.instrument != instrument)
            return false;

        orderBook.replace(snapshot.sequence, snapshot.bids, snapshot.asks);
        return orderBook.isValid();
    }

    void BookBuilder::onBookUpdate(const BookUpdate& update)
    {
        if (update.instrument != instrument)
            return;

        if (!orderBook.applyUpdate(update))
            return;

        publishMarketEvent(update.sequence, update.exchangeTimestamp);
    }

    void BookBuilder::publishMarketEvent(const SequenceNumber sequence,
                                         const Timestamp exchangeTimestamp) const
    {
        const auto bestBid = orderBook.bestBid();
        const auto bestAsk = orderBook.bestAsk();

        eventDispatcher.dispatch(MarketEvent {
            .instrument = instrument,
            .sequence = sequence,
            .exchangeTimestamp = exchangeTimestamp,
            .receiveTimestamp = Timestamp::now(),
            .bestBid = bestBid ? bestBid->price : Price {},
            .bestBidQuantity = bestBid ? bestBid->quantity : Quantity {},
            .bestAsk = bestAsk ? bestAsk->price : Price {},
            .bestAskQuantity = bestAsk ? bestAsk->quantity : Quantity {}
        });
    }
}
```

Обрати внимание: здесь сохраняется наше предыдущее решение:

**Snapshot сам по себе не создаёт `MarketEvent`.**

`applySnapshot()` только устанавливает состояние `OrderBook`.

Но здесь обнаруживается **важный следующий шаг**.

Сейчас `OrderManager` кладёт `Order` в:

```cpp
Queue<Order>
```

а `ExecutionWorker` ждёт:

```cpp
Queue<ExecutionWorkItem>
```

Значит, надо либо сделать `orderQueue` сразу `Queue<ExecutionWorkItem>`, либо оставить две очереди и адаптер. Я бы выбрал **первое** — меньше сущностей и нет лишней прослойки.

То есть `OrderManager` лучше сделать:

```cpp
concurrency::Queue<execution::ExecutionWorkItem>&
```

и:

```cpp
orderQueue.push(ExecutionWorkItem { it->second });
```

А execution reports должны приходить в **тот же `executionQueue`**.

## И здесь я бы остановился перед следующей правкой

Есть ещё одна архитектурная проблема, которую сейчас лучше не замаскировать.

`BinanceExecutionReportSource` сейчас имеет:

```cpp
setExecutionReportHandler(...)
```

а после перехода на worker правильная схема должна быть:

```text
Exchange
   │
   ▼
BinanceExecutionReportSource
   │
   │ callback / socket thread
   ▼
Queue<ExecutionWorkItem>
   │
   ▼
CPU-3 ExecutionWorker
   │
   ├── Order → Gateway
   │
   └── ExecutionReport → OrderManager / PositionManager
```

То есть **`IExecutionReportHandler` вообще не должен находиться непосредственно между Exchange и ExecutionReportSource**.

И это уже изменение интерфейса:

```text
IExecutionReportSource
BinanceExecutionReportSource
ExecutionReportHandler
ExecutionWorker
Application
```

Я бы сделал это следующим изменением, прежде чем собирать проект.

И ещё один момент: в твоём `ConditionVariableQueue` сейчас есть **критическая ошибка**:

```cpp
lock.~lock_guard();
```

Так делать нельзя — после ручного вызова деструктора `lock_guard` выйдет из scope и будет уничтожен второй раз.

То есть вместо этого:

```cpp
std::lock_guard lock { mutex };
...
lock.~lock_guard();
condition.notify_one();
```

нужно сделать:

```cpp
{
    std::lock_guard lock { mutex };

    if (closed)
        return;

    values.push_back(std::move(value));
}

condition.notify_one();
```

То же самое для `close()`.

Это стоит исправить **до запуска многопоточного pipeline**.
